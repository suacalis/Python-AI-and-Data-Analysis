9 · API Kullanmak


Python uygulamaları API'ler aracılığıyla dış hizmetleri kullanabilir. Örnek olarak güncel hava durumunu ve döviz kurlarını API'lerle nasıl alacağımıza ve ChatGPT'yi Python uygulamalarına nasıl entegre edeceğimize bakacağız.



İnternet kabaca şöyle çalışır: Web tarayıcınıza bir URL —bir adres— girer ve Enter'a basarsınız. Bilgisayarınız o adresin arkasındaki web sunucusuna bir istek gönderir ve sunucu size tarayıcınızın gösterebileceği bir HTML sayfası biçiminde bir yanıt gönderir. HTML hakkında daha fazlasını kitabın bir sonraki bölümünde öğreneceksiniz. Web sitelerini tasarlamak ve içerik göstermek için kullanılır. Tüm sistem, biz insanların içerikleri görebileceği ve sayfadan sayfaya tıklayabileceği biçimde tasarlanmıştır.



Uygulama programlama arayüzleri (API'ler) benzer biçimde çalışır; ama insanlar için değil, programlama arayüzleri olarak makineler için tasarlanmıştır. API'lerin de bir URL'si vardır; ama genellikle bir HTML sayfası döndürmezler; bunun yerine örneğin ihtiyacımız olan tüm veriyi içeren bir JavaScript Object Notation (JSON) belgesi döndürürler.



Cihazlarımızın İnternet'e gönderdiği isteklerin çoğu API istekleridir. Bunun bir nedeni, cep telefonlarımızda çalışan uygulamaların uygulamada gösterilecek veriyi almak için bir web sunucusuyla bir API üzerinden iletişim kurmasıdır. Öte yandan pek çok web sitesi de, gösterilecek veri çoğu zaman doğrudan HTML sayfasının parçası olmayıp sunucudan bir API ile dinamik olarak yüklenecek biçimde programlanır. Her iki durumda da web sitesi işletmecisi hem sağlanan API'yi hem de o API'yi kullanan uygulamayı ya da web sitesini geliştirir. Ancak bu, böyle API'lerin herkese açık olmadığı, yalnızca ön yüz (uygulama ya da web sitesi) ile arka uç (web sunucusu) arasındaki iletişime hizmet ettiği anlamına da gelir.



Ancak bazılarını ücretsiz bile kullanabileceğimiz pek çok herkese açık API de vardır; bu bölümde tam olarak bunu yapacağız. Böyle herkese açık API'ler, önce bir yerden alınması gereken verilere, örneğin hava durumu verisine erişmemizi sağlar. İlk örneklerimiz için hava durumu hizmetlerinin verisine erişen Open-Meteo API'sini kullanacağız. Bazı API'ler için isteklerinize eklenmesi gereken bir API anahtarı almak üzere önceden kaydolmanız gerekir. Sorgu kotasına bağlı olarak bazı API'ler belirli bir ücret de alır. Diğer API'ler ücretsiz sürümlerinde yalnızca saatte ya da günde belirli sayıda sorguya izin verir. Open-Meteo API'si ise kitaba göre tümüyle ücretsizdir, anahtar gerektirmez ve kısıtlama olmadan kullanılabilir; ayrıca https://www.open-meteo.com adresinde çok iyi belgelenmiştir, bu da kullanımını çok kolaylaştırır. (Not: Open-Meteo'nun kendi kullanım koşullarına göre ücretsiz erişim ticari olmayan kullanım içindir ve günlük istek sınırları vardır; güncel koşulları sitesinden denetleyin.)



Bu sayfa nasıl çalışır? Kodlar tarayıcıda Pyodide ile çalışır. requests paketi pyodide-http ile tarayıcının kendi istek mekanizmasına bağlandı; yani istekler gerçekten İnternet'e gider. Ancak tarayıcı yalnızca izin veren (CORS başlığı gönderen) API'lere erişebilir; Open-Meteo buna izin verir.


Örnek yanıtlar: Bir istek başarısız olursa (bağlantı yok, API anahtarı yok, CORS engeli ya da hata kodu), sayfa kitaptaki akışın sürmesi için o URL'ye ait örnek bir yanıt kullanır ve bunu çıktıda [sayfa] … satırıyla açıkça yazar. Örnek yanıtlar kitaptaki çıktılardan alınmıştır; saatlik sıcaklıklar ve ürün listesi kitaptaki şekillerden yaklaşık olarak üretilmiştir. Sol paneldeki Çevrimdışı mod ile her zaman örnek yanıtları kullanabilirsiniz.


ChatGPT API'si (9.4): Ücretlidir ve kişisel bir anahtar gerektirir. Anahtarınızı sol paneldeki kutuya girerseniz yalnızca bu sekmenin belleğinde ve sanal .env dosyasında tutulur; hiçbir yere kaydedilmez, sayfa yenilenince silinir. Anahtar girmezseniz bu hücreler açıklayıcı bir hata verir; kitaptaki çıktılar yanlarında gösteriliyor.

9.1"requests" ile API İstekleri



Python'da API istekleri yapmak için sık sık pip install requests ile kurduğumuz requests paketini kullanırız:






Az önce gösterilen kodu bir Jupyter Notebook hücresine yazarsak artık data değişkeninde saklanan yanıtı görebilir ve sonraki kod hücrelerinde onunla çalışmaya devam edebiliriz. requests.get(url) çağrısı asıl API isteğimizi gerçekleştirdi. GET, bir API üzerinden veri alan ya da eylem gerçekleştiren HTTP yönteminin adıdır. Alternatif olarak POST yöntemi de vardır. Bu, örneğin bir web sitesinde giriş alanları olan bir formu gönderirken, kaydolurken ya da oturum açarken kullanılır. Ama POST API'lerle de kullanılır; örneğin bir meteoroloji istasyonu olsaydık ve ölçülen sıcaklıkları API üzerinden iletmek isteseydik. Ancak bizim GET isteğimiz yalnızca veri alır. Bu veri bize response değişkeninde sunulur. Ayrıca status_code'da isteğin başarılı olup olmadığını görebiliriz. 200 durum kodu başarıyı gösterir; 400'e eşit ya da büyük diğer durum kodları hataları gösterir. Örneğin 404 kodu, kaynağın bulunamadığı anlamına gelir.

Sonra iki para birimi arasındaki güncel döviz kurunu bize söyleyen bir API kullanmak istiyoruz. Hava durumu API'lerinin aksine döviz kuru sağlayan API'ler genellikle önce bir hesap kaydetmeden kullanılamaz; çünkü sağlayıcılar kullanımı bu yolla sınırlayabilir ve hesap başına yalnızca belirli sayıda sorguya izin verebilir. Bu kötüye kullanımı ve aşırı yüklenmeyi önler. Ayrıca API sağlayıcıları, ücretsiz kotanın yetmediği kullanıcılara ücretli planlar sunarak para kazanır. Şimdi www.exchangerate-api.com hizmetini kullanacağız ve web sitesinde bir hesap oluşturacağız. Ücretsiz planla ayda 1.500 istek yapmamızı sağlayan bir API anahtarı alırız.



İstem
https://v6.exchangerate-api.com/v6/{API_KEY}/latest/EUR API'si şunu döndürüyor. Euro cinsinden bir tutarı ABD dolarına çeviren bir eur_to_usd(eur) Python işlevi oluştur.

{"result":"success", "base_code":"EUR", "conversion_rates":{"EUR":1, "AED":4.2626, …}}






Bu hücrede gerçek bir anahtar olmadığı için API hata döndürür; sayfa örnek kur (1 EUR = 1,1623 USD) ile devam eder. Kendi anahtarınızı API_KEY'e yazarsanız canlı kuru alırsınız. Anahtarsız alternatif: Aynı sağlayıcının https://open.er-api.com/v6/latest/EUR adresi kayıt gerektirmez; tek fark, kurların "rates" anahtarında olmasıdır (aşağıdaki hücre).






ChatGPT'nin oluşturduğu eur_to_usd işlevinde def ile başlayan satırda tür ipuçları (type hints) görünür: Burada eur: float, işlevin bir float değerle çağrılması gerektiğini, sondaki -> float ise işlevin kendisinin de bir float değer döndürdüğünü belirtir. Bu, işlevimiz için kısa bir belge görevi görür ve program kodunu daha okunur kılar. Ancak Python bu tür ipuçlarını yok sayar ve işlev çağrıldığında bunlara uyulmasını zorlamaz. """ ile """ arasındaki satırlar işlevin işlevselliğini betimleyen çok satırlı bir yorumdur (docstring). Bizim için yeni olabilecek bir başka şey de, API hata döndürürse raise Exception kodunun çalıştırılmasıdır. raise ile Python'da özel hata iletileri üretebilirsiniz. İşlevi daha sonra çağıran biri bu hatayı yakalayıp oluştuğunda ne olacağını bile tanımlayabilir. Bizim durumumuzda bir hata oluşursa program sonlanır.






www.exchangerate-api.com'da kaydolduktan sonra aldığımız API anahtarını API_KEY değişkenine girmemiz gerekir. API anahtarı Python programına hiç sabit olarak yazılmamalı, bunun yerine bir ortam değişkeninde —bunu daha sonra yapacağız— ya da ayrı bir yapılandırma dosyasında, örneğin config.ini'de saklanmalıdır:



[exchangerate-api]
api_key = YOUR_API_KEY_HERE



Python programımızda bu yapılandırma daha sonra yüklenir ve API anahtarı okunur. Yapılandırma dosyalarından değer okuyup onlara değer yazabildiğimiz için dosyayı bir önbellek olarak da kullanabiliriz. Döviz kuru eur_to_usd işlevimizde bir kez yüklendikten sonra bugünün tarihiyle birlikte dosyaya yazılmalıdır. İşlev her çağrıldığında önce bugünün tarihi için bir döviz kurunun zaten var olup olmadığını denetler. Öyleyse o kur kullanılır ve kendimizi bir API çağrısından daha kurtarırız. config.ini yapılandırma dosyası şöyle görünür (bu sayfada sanal klasörde hazır; sol paneldeki Dosyalar'dan görebilirsiniz):

Yapılandırma dosyasındaki her şey bir metin olduğu için dosyadaki döviz kurunun float() ile kayan noktalı sayıya dönüştürülmesi gerekir. Basitlik adına tarihi doğrudan metin olarak saklayacağız. str(date.today()) bugünün tarihini şu biçime dönüştürür: "2026-12-24". Tarihin yalnızca eşitliğini denetlemek istediğimiz için burada datetime nesnelerine ya da benzerlerine ihtiyacımız yok. İşlev çağrısı last_updated == today olduğunu belirlerse API çağrısı bölümünün tamamı atlanır ve dönüşüm katsayısı zaten usd_rate değişkeninde vardır; dosyadan alınmıştır. Ancak last_updated != today ise döviz kuru API üzerinden yüklenir ve hem usd_rate değişkenine hem de dosyaya geri yazılır.



Bu önbellekleme yaklaşımı özellikle tekrar tekrar yapılan ve zaten her çağrıda aşağı yukarı aynı sonucu veren pahalı API çağrıları için değerlidir. API çağrıları çoğu zaman biraz yavaş olabildiği için bu, program yürütmesini gerçekten hızlandırır. Örnekte kullanılan ExchangeRate API'si ücretsiz plan kullanıcıları için döviz kurlarını zaten günde yalnızca bir kez günceller. Aynı gün farklı zamanlarda farklı kurlar döndüren başka bir API kullansaydık, önbelleğe dayalı yaklaşımımız kurları günde yalnızca bir kez güncellediğimiz için bazen güncel olmayan veri döndürürdü.



API'nin sağladığı dönüşüm katsayısını güncel tarihle birlikte bir yapılandırma dosyasına yazdık. Bunlar nadiren değişen yalnızca iki küçük değer. Ancak bunun yerine pek çok farklı şehir için —çok sayıda sayı ve başka değerden oluşan— hava durumu verisini önbelleğe alsaydık, API yanıtlarını ayrı dosyalarda ya da bir veritabanında saklamak daha mantıklı olurdu. O zaman örneğin Chicago.json adlı bir dosyamız, LA.json adlı bir dosyamız vb. olurdu. Dosyanın meta verisi son değiştirilme tarihini sakladığı için bunu, istenen konum için hava durumunun bugün zaten alınıp alınmadığını belirlemekte kullanabiliriz. Öyleyse kaydedilmiş API yanıtını dosyadan yükleriz; değilse API isteğini yapar ve yanıtı dosyaya kaydederiz. Veritabanlarıyla tüm süreç daha da zarif hâle gelir: Hava durumu geçmişini ya da önümüzdeki günlerin tahminini de orada saklayabilir ve analizler yapabiliriz. Bunun nasıl yapılacağına kitabın 11. bölümünde bakılıyor.






Son hücrede requests.get'e parametreleri URL'ye elle eklemek yerine params= sözlüğüyle verdik; requests URL'yi kendisi kurar ve özel karakterleri doğru biçimde kodlar.




9.2Özel SDK'larla API Erişimi



Pek çok API JSON verisi döndürür. Bu, önceki kısımda tanıtılan yaklaşımı çeşitli kaynaklardan veri almak için kullanabileceğimiz anlamına gelir: Önce requests modülünü içe aktarırız, sonra gerekli tüm parametreleri URL'de ve gerekirse bir API anahtarını belirterek requests.get ile API URL'sine bir istek göndeririz. API daha sonra bir yanıt döndürür; bunu response.json() ile okur ve ona erişebilmek için bir Python sözlüğüne ya da listesine dönüştürürüz. JSON yerine CSV, XML ya da tümüyle farklı bir biçimde veri döndüren API'ler de vardır. Bu durumlarda da requests modülünü kullanabiliriz. Ancak bu tür durumlarda yanıtı response.text ile metin olarak alır ve oradan çalışırız. Tek tek biçimler için bunun nasıl işlediğini kitabın 4. bölümünde öğrendiniz.



Pek çok geliştirici farklı API'ler için kendi yazılım geliştirme kitlerini (SDK) oluşturmuştur. Çeşitli programlama dilleri için SDK'lar vardır. API'lere requests ile erişmenin evrensel yöntemine bir alternatif sunarlar ve genellikle belirli bir API için özel olarak tasarlanmışlardır. Bir API için böyle bir SDK varsa genellikle ilgili modülü pip ile kurabilir ve ardından API URL'sini program koduna kendimiz girmek ya da GET istekleri vb. ile uğraşmak zorunda kalmadan basitçe işlevleri çağırabiliriz. Daha önce hava durumu verisini almak için kullanılan Open-Meteo API'sinin de bir SDK'sı vardır; ama sonraki örnek için OpenWeatherMap hizmetini kullanacağız. Bunun için pip install pyowm ile ilgili Python paketini kurmamız ve bir API anahtarı almak için https://openweathermap.org'da bir hesap oluşturmamız gerekir.



Salt okunur — pyowm Pyodide'de yok ve OpenWeatherMap API anahtarı gerektirir
from pyowm import OWM

owm = OWM('Enter API key here')
mgr = owm.weather_manager()
observation = mgr.weather_at_place('Chicago, US')

weather = observation.weather
temperature = weather.temperature('fahrenheit')["temp"]

print(f"Temperature: {temperature}°F.")



pyowm paketini kullanmak için onu pip install pyowm ile kurmamız gerekir. Ardından API anahtarımızı verip weather_at_place ile belirli bir konum için hava durumu verisini alabiliriz. Özellikle bir API'ye farklı URL'ler altında sunulan çeşitli istekler yaparken bir SDK kullanmak requests kullanmaktan daha rahat olabilir. SDK'lar tek bir API için özel olarak, çoğu zaman API sağlayıcısının kendisi, bazen de başkaları tarafından tasarlanır. Ancak perde arkasında bir SDK tam olarak daha önce yaptığımız şeyi yapar. weather_at_place işlevini çağırdığımızda içeride requests.get'i çağırır ve orada döndürülen JSON'u işler. Ama biz kullanıcılar için teknik ayrıntılar soyutlandığı için işleri kolaylaştırır ve en önemli şeye odaklanmamızı sağlar.



Bu fikri somutlaştırmak için Open-Meteo'ya küçük bir "SDK" yazalım: URL ve parametre ayrıntılarını bir sınıfın içine saklıyoruz; kullanıcı yalnızca anlamlı bir işlev çağırıyor.







9.3API Verisini Görselleştirmek ve Analiz Etmek



Bir API üzerinden veri aldığımızda bu veri bize genellikle bir Python sözlüğü ya da bir liste biçiminde sunulur. Ardından güncel sıcaklık ya da daha önce sözü edilen euro-dolar kuru gibi bizi ilgilendiren değerlere doğrudan erişebiliriz. Sonuçlar bir liste olarak sunuluyorsa onun üzerinde dolaşabilir, tek tek elemanları yazdırabilir ya da onlarla çalışmaya devam edebiliriz.



Şimdi bir API kullandığımız ve döndürdüğü veriyi Matplotlib ile görselleştirdiğimiz iki örneğe bakacağız. Veriyi Matplotlib'in çalışabileceği bir biçime dönüştürmemiz gerekir. Bir çizgi grafiği için örneğin iki listeye ihtiyacımız var: biri x değerleri, biri y değerleri. Belirli bir gün için sıcaklık eğilimini bir çizgi grafiği olarak çizmek istiyoruz. Bunun için istenen tarihe ait hava durumu verisini Open-Meteo API'sinden alırız —bu hem geçmiş tarihler hem de tahminler için çalışır— ve ölçüm saatini x ekseni değerleri, sıcaklıkları da y değerleri olarak kullanırız.



İstem
https://api.open-meteo.com/v1/forecast?latitude=41.85&longitude=-87.65&hourly=temperature_2m&temperature_unit=fahrenheit&start_date=2026-07-01&end_date=2026-07-01 şunu döndürüyor:

{…, "hourly": { "time": ["2026-07-01T00:00", "2026-07-01T01:00", …],
               "temperature_2m": [89.4, 86.7, …] } }

Günün her saati için sıcaklığı gösteren bir çizgi grafiğini Matplotlib ile oluşturan Python kodu yaz. API çıktısında listelenen son saat, ertesi günün gece yarısı (00:00) olduğu için atlanmalı.






İki not: (1) İstemde "son saat ertesi günün 00:00'ı" deniyor; ama start_date ile end_date aynı gün olduğunda Open-Meteo yalnızca 00:00–23:00 arasındaki 24 saati döndürür. ChatGPT'nin kodu da hiçbir şeyi atlamıyor; yani istemdeki varsayım yanlış, kod doğru (yukarıdaki son satır 24 saati gösteriyor). (2) /v1/forecast uç noktası yalnızca yaklaşık son 3 ayı kapsar. 9.4ChatGPT API'si



ChatGPT ve diğer büyük dil modellerini (BDM) yalnızca bir tarayıcı ve uygulama üzerinden kullanmakla kalmaz, bir API aracılığıyla Python uygulamalarımıza da entegre edebiliriz. Özellikle elimizde metin ya da görüntü verisi olduğunda bir BDM, basit Python araçlarıyla başaramayacağımız görevleri çözebilir. Örneğin ChatGPT veri temizliği ya da kategorizasyon, uzun metinleri özetleme ya da çeviri için kullanılabilir.



Aşağıdaki örneklerde OpenAI'nin ücretli API'sini kullanacağız. Kullanmak için hesabınıza birkaç dolar yatırmanız gerekir. Standart API istekleri çok ucuz olsa da —özellikle temel bir model seçersek bir sentin yalnızca bir kesri kadar— zamanla çok sayıda istek yaparsanız bakiyeniz hızla tükenebilir.



https://platform.openai.com'da oturum açıp bakiyemizi yükledikten sonra Python programımızda kullanmak üzere bir API anahtarı oluşturabiliriz. openai paketini pip install openai ile kurarız.



Bu sayfada openai ve dotenv: Gerçek openai paketi Pyodide'de çalışmaz. Kitaptaki kod değişmeden çalışsın diye sayfa, sanal klasöre aynı arayüzü (OpenAI(...), client.responses.create, client.images.generate) requests ile sağlayan küçük bir openai.py uyumluluk katmanı koydu; bu, 9.2'deki "SDK perde arkasında requests kullanır" fikrinin canlı bir örneği. Dosyayı sol panelden açıp okuyabilirsiniz. python-dotenv ise PyPI'den micropip ile kurulur (kurulamazsa yine küçük bir yedek kullanılır). Anahtarınızı sol paneldeki kutuya girip .env'ye yaz'a basınca sanal .env dosyası oluşur ve dotenv.load_dotenv() onu okur.






API anahtarını Python programımızda düz metin olarak tutmamak için burada bir ortam değişkenine erişiyoruz. dotenv modülüyle —pip install python-dotenv ile kurulur; kitapta pip install dotenv yazıyor, ama doğru paket adı python-dotenv'dir— API anahtarını Python programımızla aynı klasörde bulunan .env adlı bir dosyaya şöyle yazmak mümkündür: OPENAI_API_KEY=…. Ardından program içinde os.environ.get("OPENAI_API_KEY") ile okunabilir. summarize işlevimiz bir metin alır ve onu genel talimatları içeren bir sistem istemiyle (instructions) ve bir kullanıcı istemiyle (input) birlikte ChatGPT API'sine gönderir. Deneme çağrısında verilen "Some text" metni kitapta "This is generic placeholder text." olarak özetlenmiş. Ancak örneğin CNN.com RSS akışı aracılığıyla alabileceğimiz daha uzun bir metin de verebiliriz. Bunu pip install feedparser ile kurduğumuz feedparser modülüyle yaparız:

import feedparser

RSS_URL = "http://rss.cnn.com/rss/edition_world.rss"

print("Title:", feed.entries[0].title)
print("Link:", feed.entries[0].link)
print("Description:", feed.entries[0].summary)
print("Summary:", summarize(feed.entries[0].summary))

ChatGPT API'sinin faturalandırması girdi belirteçlerine ve çıktı belirteçlerine (token) dayanır. Seçilen modele bağlı olarak bir milyon belirtecin maliyeti birkaç sentten birkaç dolara kadar değişir. Girdi belirteci sayısı istemimizin (sistem istemi dâhil) uzunluğuna, çıktı belirteci sayısı yanıtın uzunluğuna bağlıdır. Kullanılan belirteç sayısını da gösterebiliriz:






Kitaptaki çıktıda API yanıtı "ok"'a ek olarak 20 girdi belirteci ve 102 çıktı belirteci kullanıldığını görüyoruz. Bir belirteç çoğu zaman üç ila dört karakterlik bir metin parçasıdır. Bu, 20 sayısını da açıklar. Yanıtın 102 çıktı belirteci uzunluğunda olması, ChatGPT API'sinin asıl yanıtla birlikte bazı meta veriler göndermesindendir. (Daha doğrusu: gpt-5-nano bir akıl yürütme modelidir; çıktı belirteçlerine yanıttan önce üretilen ve görünmeyen "akıl yürütme belirteçleri" de dâhildir. Bunları response.usage.output_tokens_details.reasoning_tokens'ta görebilirsiniz.) Kullandığımız model "gpt-5-nano" olarak adlandırılıyor. Milyon girdi belirteci başına 0,05 $ ve milyon çıktı belirteci başına 0,40 $ fiyatla sorgumuzun toplam maliyeti bir sentin yüzde birinden azdır. Ancak sorgumuz 10 kat daha karmaşık olsaydı ve 10 kullanıcı günde bu türden 10 sorgu gönderseydi, maliyet 10 günün sonunda yarım ABD dolarından biraz az olurdu.

ChatGPT API'si ve diğer BDM'lerin API'leriyle girdi olarak yalnızca düz metin vermek değil, görüntüler, belgeler ve diğer dosyaları da eklemek mümkündür. Bu API'ler çıktı olarak görüntü, video ve diğer dosya biçimlerini de üretebilir. Aşağıdaki kod örneğinde BDM'ye bir görüntü dosyası gönderiyor ve görüntüde ne görülebileceğini soruyoruz. (Sayfadaki images/fruit.jpg, Bölüm 8'deki çizilmiş soyulmuş muz görselidir.)






Kitaptaki çıktı (gerçek fotoğrafla):
A partially peeled banana. The yellow peel is curling away from the white inner fruit, set against a plain light background.
Input Tokens: 1634
Output Tokens: 248



Model görünüşte çok daha karmaşık bir görevi ele almış olsa da maliyet sonuçta basit deneme isteğimizdekinden yalnızca yaklaşık dört kat fazladır. Bazen görüntüyü göndermeden önce yeniden boyutlandırarak işleri daha da iyileştirebilirsiniz. Görüntü verisini API'ye vermek için dosyayı okuyup Base64 biçimine dönüştürmeniz gerekir. decode("utf-8") bundan şuna benzeyen uzun bir metin üretir: '/9j/4AAQSkZJRg…' (kitaptaki 85 KB'lık fotoğraf için 100.000 karakterden uzun). Görüntü verisinin tamamı bu metinde kodlanmıştır ve onu API'ye verebiliriz.






Bir Base64 metni, API'ler görüntü ya da başka dosyalar ürettiklerinde programımıza çoğu zaman döndürdükleri şeydir. Bu veriyi daha sonra bilgisayarımızda bir dosyaya geri kaydedebiliriz, örneğin: f.write(base64.b64decode(image_base64)). Ancak bazı API'ler üretilen görüntüyü yanıta hiç eklemez, yalnızca görüntüyü belirli bir süre içinde alabileceğimiz bir URL verir. Bu durumda görüntünün indirilmesini requests.get ile başlatabiliriz.






Görüntü üretimi metin isteklerinden belirgin biçimde pahalıdır. Kitaptaki import base64 satırı eksik olduğu için kod NameError: name 'base64' is not defined verirdi; burada eklendi. Model adı kitaptaki gibi bırakıldı; hesabınızda bu model yoksa API'nin hata iletisinde geçerli adları görürsünüz.



ChatGPT ile Python kodu üretmek istiyorsanız elbette API anahtarlarını program koduna eklememelisiniz. Bu yüzden örneklerimizde gösterildiği gibi API anahtarını .env adlı bir dosyaya (içerik: API_KEY=…) kaydetmek ve bu dosyayı programın başında dotenv.load_dotenv() ile yüklemek mantıklıdır. Ayrıca ChatGPT ve benzeri araçlar program kodu üretirken sık sık çok sayıda hata yapar; çünkü bir API yanıtının neye benzediğini bilmezler, işlev ve parametre adları basitçe tahmin edilir ya da API'nin eski bir sürümü kullanılır. Burada API'nin nasıl kullanılacağına dair bilgileri —örneğin API belgelerinde bulunan— isteme eklemek yardımcı olur. requests ile bağlandığımız ve JSON döndüren API'ler için JSON'dan ilgili alıntıları isteme eklemek yardımcı olur. Önce işlevsel bir minimal programı kendiniz yazmak ve ardından bu kodu ChatGPT'ye verip programı belirli özelliklerle genişletmesini istemek de her zaman yararlıdır. Bu tür minimal programları resmî web sitelerinde, API belgelerinde, bloglarda ya da web forumlarında sıklıkla bulabilirsiniz. Burada kendiniz kod yazmanın, arama yapmanın ve ChatGPT kullanmanın birleşimi etkilidir. Yürütme sırasında ortaya çıkan hata iletilerini ChatGPT'ye vermek de BDM'nin program kodunu buna göre uyarlayabilmesine yardımcı olur.
